<h1 align="center">API Кинополки</h1>
<p align="center">Каталог фильмов и сериалов, полки зрителей и поиск по смыслу.</p>

Серверная часть Кинополки хранит каталог и историю зрителей в PostgreSQL. Через HTTP API можно найти фильм по описанию, поставить оценку, написать рецензию и собрать подборку. Для запроса «фантастика про одиночество в космосе» сервер получает вектор текста от ML-сервиса и ищет близкие произведения с помощью pgvector.

## Возможности

| Раздел | Что делает API |
| --- | --- |
| Каталог | Загружает фильмы и сериалы из TMDB, хранит описания, жанры, состав съёмочной группы, сезоны, трейлеры и кадры. Внешние рейтинги и оценки зрителей Кинополки учитываются отдельно. |
| Поиск и рекомендации | Ищет по названию и фильтрам, находит похожие произведения по эмбеддингам. КиноГид учитывает запрос и отметки зрителя на полке. |
| Профиль и полка | Управляет сессиями, друзьями, избранным и статусами просмотра. Хранит оценки произведений и отдельных серий. |
| Рецензии | Позволяет поставить оценку без текста или опубликовать её вместе с рецензией. Поддерживает отметку спойлеров и реакции зрителей. |
| Подборки и модерация | Сохраняет состав и порядок фильмов. Администратор может публиковать подборки от имени платформы, скрывать их и управлять блокировками аккаунтов. |

## Стек

**NestJS · TypeScript · TypeORM · PostgreSQL 17 · pgvector · Docker Compose · Jest**

Векторы хранятся в `title_embeddings`. Миграция создаёт индекс HNSW с классом операторов `vector_cosine_ops` для поиска ближайших соседей по косинусному расстоянию. [Миграция индекса HNSW](src/database/migrations/1795359000000-AddHnswIndex.ts)

## Локальный запуск

Понадобятся Node.js с npm и Docker Compose. Команды для PowerShell выполняются из корня репозитория. Проект проверялся на Node.js 26.

**1. Подготовьте конфигурацию.** При первом запуске скопируйте шаблон и задайте `POSTGRES_PASSWORD` в `.env`. Для существующей базы укажите действующие параметры подключения.

```powershell
npm.cmd ci
Copy-Item .env.example .env
```

**2. Запустите PostgreSQL, примените миграции и запустите API.**

```powershell
docker compose up -d --wait
npm.cmd run typeorm -- migration:run -d src/database/data-source.ts
npm.cmd run start:dev
```

**3. Откройте** `http://127.0.0.1:3000/titles`. На новой базе список будет пустым. При прямом обращении к NestJS используйте пути из таблицы ниже. Префикс `/api` добавляется при обращении через прокси фронтенда.

## Как наполнить каталог

Укажите `TMDB_READ_ACCESS_TOKEN` в `.env`. Пример загружает по одной странице фильмов и сериалов, а затем дополняет карточки медиаматериалами и сведениями о людях.

```powershell
node --env-file=.env -r ts-node/register src/import/import-catalog.ts movie 1
node --env-file=.env -r ts-node/register src/import/import-catalog.ts series 1
node --env-file=.env -r ts-node/register src/import/enrich-catalog.ts media 40
node --env-file=.env -r ts-node/register src/import/enrich-catalog.ts people 20
```

**Рейтинги Кинопоиска.** Команда `npm.cmd run ratings:import -- --kinopoisk-xml` сопоставляет идентификаторы каталога и получает рейтинг из XML Кинопоиска. Произведения без однозначного соответствия или опубликованной оценки пропускаются.

**Семантический поиск.** После импорта рассчитайте эмбеддинги каталога и запустите ML-сервис. Бэкенд обращается к нему по `ML_SERVICE_URL` (по умолчанию `http://127.0.0.1:8000`). Для генеративной части КиноГида задайте `OPENROUTER_API_KEY`. [Инструкция ML-сервиса](https://github.com/xajjne/kinopolka-ml-service)

## Примеры запросов

| Метод и путь | Результат |
| --- | --- |
| `GET /titles?q=Интерстеллар` | Поиск по названию |
| `GET /titles/:id` | Карточка произведения с медиаматериалами и рейтингами |
| `GET /titles/:id/community` | Средняя оценка, распределение голосов и рецензии |
| `GET /titles/:id/similar` | Подбор похожих произведений |
| `GET /search/semantic?q=путешествие во времени` | Семантический поиск по каталогу |
| `POST /search/guide` | Ответ КиноГида на текст в поле `q` |

## Проверка

```powershell
npm.cmd run build
npm.cmd test -- --runInBand
npm.cmd run test:db
```

Для интеграционных тестов требуется база с применёнными миграциями, фильмами, сериалами и рассчитанными эмбеддингами. Тестовые записи создаются внутри транзакций с откатом.
